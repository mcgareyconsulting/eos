## HIGH

### H1. `scripts/merge-import-user.ts` corrupts meeting speaking state and has no misuse guards
- `scripts/merge-import-user.ts:203-204` writes `current_speaker_id` — a field
  **nothing in the app reads**. The meetings model uses `speaking_index` (an
  integer into `speaking_order`). Lines 197-201 remove `from` from
  `speaking_order` without decrementing `speaking_index`, so any meeting where
  `from` sat at/before the pointer skips a speaker after the merge — and
  finished meetings' as-run rotation gets rewritten.
- No guard that `--from` is actually an import placeholder (e.g. requiring an
  import marker / absent Auth record). Both args are valid members, so a
  swapped `--from`/`--to` reassigns the real user's rocks/todos/issues/metrics
  to the placeholder, then **deletes the real user's `team_members` doc and
  global `users/{uid}` profile**. The usage example hardcodes
  `--database hpb-eos-prod-db`.
- `scripts/merge-import-user.ts:222-225` deletes `users/{from}` globally while
  validating only one team — if the placeholder exists on two teams, the other
  team's roster loses the profile doc.

### H2. Teammates' private to-dos leak on the Home page (pre-existing, still live)
`app/(app)/home/page.tsx:34-40,102` — the Home todos query filters only
`team_id in` + `completed_at == null`; `pureTodos` renders with no
`visibility`/owner filter, so other members' `visibility: "private"` titles
show on everyone's Home. The team To-Dos page filters correctly
(`todos/page.tsx:174`), and PR #10 fixed the same leak on the meeting page.
Predates this window (`08b1aba`), but it's a real privacy hole for a bank
client and maps directly to Jenna's Pass 14 #9 "issues must not leak" concern.

## MEDIUM

### Archive model (PR #17)
- **M1. "Closed in the meeting" is a wall-clock window, not in-meeting
  closure.** `lib/todos-archive.ts:30-47` (and issue/headline variants) select
  anything closed between `started_at` and `ended_at`+60s. A member's private
  todo checked off from their own tab, or an issue solved from the standalone
  page by someone not attending, shows "Closes Monday" and then archives early
  when someone clicks Finish. Since `startMeeting` blocks a second live
  meeting, a meeting left open all day sweeps the whole day's completions.
  (Cross-team leakage and double-archive do **not** occur; the Monday sweep
  catches anything missed — the defect is over-eager archiving only.)
- **M2. The Monday worker does unbounded full-collection scans.**
  `functions/src/archive-stale-todos.ts:55-59` — `db.collection("todos").get()`
  etc., no `where`, no pagination: every doc of all teams, including everything
  already archived, loaded into memory every Monday, forever. Add
  `archived_at == null` filters (new docs write explicit nulls) and/or
  pagination before the collections grow. Batch chunking (400), milestone and
  broadcast exclusions, and idempotency are all correct.
- **M3. Archived Issues tab "Closed On" blanks out after hydration.**
  `issues/issues-list.tsx:84-87,275-279` — the server computes `closed_on`, but
  `useCollection` replaces rows with raw Firestore docs on the first snapshot,
  which have no `closed_on`. Dates flash then become "—". Derive from live
  `archived_at` client-side. (Todos/headlines archived lists are pure server
  renders — fine.)
- **M4. Rules never tightened for the archive/vote contract.**
  `firestore.rules:119-143,159-167` — any member's client can directly write
  `archived_at` / `resolved_at` / `completed_at` / `discussed*` / `votes`.
  Concrete breakage: set `status: "solved"` without `resolved_at` → grays out
  with "Closes Monday" but is never archived by Finish or the worker (predicate
  requires `resolved_at`). The 3-credit vote cap exists only in the `castVote`
  server action. Also `rock_status_updates` create doesn't pin
  `user_id == request.auth.uid` (rules:112-116), so history entries can be
  attributed to others. Consistent with the admin-SDK-first posture, but the
  contract shipped without field-level validation — flag for the bank security
  review.

### Rocks redesign (PR #16 / merge b41d5b7)
- **M5. Archived rocks tab will throw once any rock is archived.**
  `rocks/page.tsx:105,338` — `archived_at` is passed to the client `RockRow` as
  a raw admin-SDK `Timestamp` instance, which is not RSC-serializable. Latent
  only because the archive path intentionally doesn't exist yet — will bite the
  session that builds it. (Companion: the L10 rocks segment and the due-soon
  milestone surfaces never filter `archived_at` either — L1 below.)
- **M6. Milestone edits/deletes bypass the Google Tasks mirror.**
  `rocks/actions.ts:252-272` — `updateRockWithMilestones` raw-batch-deletes and
  raw-batch-updates milestone todos without `deleteTaskForTodo`/
  `upsertTaskForTodo`, so a mirrored task lives forever after its milestone is
  removed, and retitles/re-dates never propagate. (Old path used `deleteTodo`,
  which did clean up. `deleteRock` had the same gap pre-window.) Adjacent to the
  known "milestones never mirror on create" gap already in ROADMAP.
- **M7. Ticking a milestone on the Rocks tab visually reverts.**
  `todos/actions.ts:120` only revalidates `/todos`; the Rocks tab and detail
  modal have no subscription, so `TodoCheckbox`'s optimistic state snaps back
  when the transition ends even though the write persisted. This PR made the
  Rocks tab the primary milestone-ticking surface.
- **M8. Status popover clips on narrow viewports — the "clipped dropdown" bug
  reintroduced at a new breakpoint.** `rocks/status-popover.tsx:26,57-63` —
  fixed `PANEL_W = 480` with a clamp whose upper bound goes negative under
  ~504px width: on a phone the panel is position-fixed off the left edge and
  the status radios are unreachable. Pre-#16 width was 320 (harmless);
  widening to 480 made it real.
- **M9. Edit mode re-suggests EOQ on rocks whose due date was deliberately
  cleared.** `rocks/rock-modal.tsx:177` seeds `useState(rock?.due_date ??
  defaultDue)` and all edit call-sites pass `defaultDue={eoq}` — open Edit on a
  no-due rock, save an unrelated change, and the EOQ due date silently returns.
  Directly contradicts P2-6 ("null when cleared, never re-forced").

### Session C (PR #14)
- **M10. `deleteHeadline` is missing the broadcast guard** that
  `setHeadlineDiscussed`/`setHeadlineArchived` both have
  (`headlines/actions.ts:50-55`). Broadcast copies carry the target team's
  `team_id`, so `requireTeamDoc` passes and any member can POST the action
  directly and destroy an org-wide read-only headline. UI hides the button;
  the endpoint doesn't.
- **M11. Moving an issue to long-term via the edit modal doesn't clear the
  live meeting's discuss pin.** `issues/actions.ts:76-105` (`updateIssueMeta`)
  writes `type: "long"` with none of the pin cleanup that `setIssueType`
  (211-230) does — a pinned "Discussing" issue edited to LT leaves
  `meeting.current_issue_id` stale.

### Aug 3 batch (PRs #11–#13)
- **M12. Home `DueLabel` still UTC-parses due dates.**
  `app/(app)/home/page.tsx:273` — bare `new Date("YYYY-MM-DD")` vs local
  midnight: an item due today renders red/overdue all day for any US-timezone
  user. Same page, same diff fixed the identical class 160 lines up with
  `isDueWithinDays`; `lib/dates.ts` `daysUntil`/`toLocalDate` are the fix.
- **M13. Home queries break for many-team users.**
  `app/(app)/home/page.tsx:38-48` — three unchunked `team_id in` queries; the
  rocks one stacks `in × in` and hits Firestore's 30-disjunction cap at
  **16 teams** (hard page error); the others at 31. `lib/firestore-in.ts`
  names this exact call-site as needing `chunkForInQuery`. (Known-remaining in
  ROADMAP; now contradicted by an inline "fine" comment.)

### Scorecard restyle (PR #18)
- **M14. Goal-less metrics render a contradictory status.** `trendStatus`
  returns `ok` when `goal == null` (green "On-track" pill), but `hitRate` never
  counts a hit without a goal — so the row shows On-track next to "0/13 hit"
  and a 0% bar, and the expand panel says "Periods hit: 0 of 13"
  (`scorecard-grid.tsx` meta line, `metric-expand.tsx`). Suppress the hit-rate
  UI (or the counting) when `goal == null`.
