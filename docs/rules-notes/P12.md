# P12 rules notes (access-change audit records)

No rule change is required for the app to work: every `audit_log` row is
written by the Admin SDK (server actions) or by the Cloud Function.

Check, when `firestore.rules` is rewritten:

- `audit_log`: admin read only, no client writes (unchanged intent).
- The new rows live in `audit_log` with `entity_type` of `access_change` or
  `admin_view`. Both are readable by admins under the existing rule.
- Admin data exports (docs/EXPORT.md) add rows with `entity_type:
  "data_export"`, written by the Admin SDK before the file is sent. Same
  rule, no change. Refused attempts add rows too (`outcome: "refused"`).
- Print-export tokens live in `export_print_tokens` (Admin SDK only). The
  rules list it with `allow read, write: if false`, next to
  `oauth_csrf_states`; that is what the default already gives, written out
  so a rewrite doesn't open it.
- Doc ids for admin-view rows are deterministic:
  `admin_view__{adminUid}__{teamId}__{YYYY-MM-DD}` (UTC day).
- New documents fields written to audited collections by server actions:
  `updated_by`, `updated_at`, `deleted_by`, `deleted_at`. If the rules
  restrict a `users` document to a fixed field list for client updates, this
  does not matter (clients do not write), but any rule that diffs `users`
  fields with `affectedKeys()` for an owner update must not be confused by
  the server-written stamp (server writes bypass rules).
